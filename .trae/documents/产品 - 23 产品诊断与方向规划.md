# FlowSpark 产品诊断与方向规划

> 版本：v1.0 ｜ 日期：2026-07-29 ｜ 作者：CodeBuddy（基于代码核对）
> 关联：产品 - 21 Phase 2A AI Daily Coach + Goal Setup PRD、产品 - 22 Phase 2A AI 留存实验计划

## 0. 背景与目标

作者怀疑"没有自己的大模型 → 项目只是个 todolist → 自嗨产品"。

本文基于代码实际实现，核对"设计承诺 vs 代码现实"，给出适合**个人自用**阶段的产品方向。

**结论先行**：项目不是没有人生系统，是系统的"大脑"写好了却插在了没人每天看的地方。

## 1. 核心发现

项目有两套关键设计文档：
- `docs/superpowers/specs/2026-07-23-chat-as-primary-surface-design.md`：声明 `/chat` 是主入口、系统真正存在的地方。
- `docs/superpowers/specs/2026-07-23-global-system-conversation-design.md`：声明聊天应消费记忆分层（自我画像 / 偏好 / 摘要）。

但代码现实是——聊天内核只接了最薄一层数据（`src/lib/chat/context.ts` 仅传入 goals + todayActions 的标题）。而已经写出来的"人生系统智能"（Self Model）非常成熟，却只被喂给 `/profile` 与 `/profile/ai-insights`，每天打开的 `/chat` 完全看不到。

**一句话**：大脑装在了侧边间（profile），每天住的主卧（chat）只有排日程的壳。这才是"感觉只是 todolist"的根源——不是没有大模型，不是没有智能，是智能没接到每天说话的地方。

## 2. 差距清单（设计承诺 → 实现 → 是否接进 /chat 主界面）

| 设计承诺 | 代码实现 | 接进 /chat？ |
|---|---|---|
| 目标 + 今日行动上下文 | ✅ `src/lib/chat/context.ts` | ✅ 是 |
| completed 数据层过滤 | ✅ `context.ts:42` | ✅ 是 |
| Self Model 周画像/今日个性化 | ✅ `src/lib/self-model.ts`（成熟） | ❌ 仅 profile/ai-insights |
| 偏好记忆（DB 持久化） | ✅ `src/lib/system-memory/preferences.ts` | ❌ 仅 profile；chat 内为硬编码 |
| 连续天数 / 节奏 | ✅ `src/lib/streaks.ts` | ❌ 未进 chat |
| 推荐信号 / 采纳完成率 | ✅ `src/lib/ai/analyticsStore.ts` | ❌ 未进 chat |
| 摘要记忆（>20 轮压缩） | ✅ `src/lib/system-memory/summarized.ts` | ❌ 仅 localStorage 客户端，服务端拿不到 |
| 完成闭环（说"做完了"→落库） | ⚠️ `src/app/api/chat/complete/route.ts` 只做检测+返回 draft，写库在 UI 确认后 | ⚠️ 半通 |
| 创建行动闭环（说"记一条"→落库） | ❌ `/api/chat` 下无创建接口 | ❌ 缺失 |
| 短期工作记忆 20 轮 | ⚠️ chat 只传 `history.slice(-10)`（MAX_HISTORY=10） | ⚠️ 仅 10 轮 |

关键代码证据：
- chat 上下文只含 goals + todayActions：`src/lib/chat/context.ts:7-11`
- Self Model 仅在 profile 页消费：`src/app/(authenticated)/profile/page.tsx:107`、`src/app/(authenticated)/profile/ai-insights/page.tsx:273`
- chat 流式接口仅用 getChatContext：`src/app/api/chat/stream/route.ts:49`
- 完成检测存在但仅返回 draft：`src/app/api/chat/complete/route.ts:55-64`

## 3. 护城河分析（为什么通用 agent 吃不掉你）

- **私人纵向数据**：目标、行动、连续打卡、周画像，属于用户、年复一年积累；通用 agent 记忆扁平可丢。
- **有判断力的领域规则层**：`src/lib/chat-agent/action-ranking.ts` 的 `compareActionsForToday`（逾期 > 优先级 > 核心 > 主目标 > 截止日）是通用 agent 没有的"人生 OS 判断"。
- **数据层完成过滤**：`context.ts:42` 系统分得清已完成/未完成，无数据库的聊天框做不到。
- **闭环写入**：confirm→commit 能把话变成真实落库（设计如此，需补全 P2）。

价值不在"聊得更好"，而在"它越来越懂你、并替你行动"。这是通用 agent 的真空地带。

## 4. 产品方向（个人自用阶段）

验证标准：**每天打开 /chat，它给的建议是否明显比直接开 ChatGPT 更好？**
目前不是，因为 chat 看不到连续天数、节奏画像、偏好。把第 2 节 ❌ 接上即成立——且全部不依赖大模型，纯是你自己的数据。

方向不是"换模型"或"加功能"，而是：**把所有已写好的个性化数据集中接进 /chat 主界面，让聊天成为唯一也最聪明的使用面。**

两个心结的回答：
1. "没有自己的大模型" → 从来不是问题。护城河是私人数据 + Self Model + 闭环，正是垂直 AI 标准打法。
2. "只是 todolist" → 错在 chat 没接大脑，不在产品本质。大脑已有，只是没插电。

## 5. 实施规划（按杠杆排序）

- **P0（最高杠杆，纯接线）**：改 `getChatContext` + `prompt.ts`，把 `buildSelfModelCards` / `buildTodayPersonalization`、偏好、连续天数、近 7 天完成率喂进系统提示词。做完 chat 立刻从"todolist 壳"变"懂我的系统"。
- **P1（记忆闭环）**：chat 历史从 10 轮提到 20 轮；把客户端 `summarized.ts` 摘要在请求时一并带上，实现"更早摘要记忆"。
- **P2（闭环补全）**："做完了"已有检测路由、写库靠 UI 确认；"记一条行动"在 chat 无创建接口。补齐 confirm→commit，让 chat 真正替你写数据。
- **P3（自用验收）**：别急着为别人做通用化。先自己每天用，验证 P0 后 chat 建议是否真比 ChatGPT 贴你。成立再谈下一步。
