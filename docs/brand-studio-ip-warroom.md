> **文档定位**：本文件是 Brand Studio 重构为「个人 IP 全生命周期作战平台」的**单一事实来源（single source of truth）**，持续迭代。当前处于**方案打磨阶段，未开工**；待产品负责人确认"着手开发"后进入实施。
>
> **与产品总蓝图关系**：`docs/life-planner-blueprint.md` 是 FlowSpark 总体产品蓝图（"内容创作者的私有成长 OS"）。本文件是其**垂直深化**——聚焦 Brand Studio 这一工作台如何支撑"个人 IP 打造"这一核心场景，并把它升级为**一人公司 / 类 MCN 操盘驾驶舱**。两者在"人设沉淀""内容资产树""周回顾"上共用同一套底座，不重复造轮子。
>
> **当前代码现状（实施起点）**：
> - `src/lib/contentBrand.ts` 仍是**单账号最小版**：`content_ideas`(选题) + `content_calendar`(日历，仅 `platform` 字符串) + 内容资产树，全部经 RLS `user_id = auth.uid()` 隔离，无示例数据。

## 0. 重新定义：它是什么

不是"视频号排期染色台"，而是 **一人公司 IP 操盘驾驶舱（OPC War Room）**：

> 以**独立 IP 定位**为根，AI 贯穿「**定位 → 人设沉淀 → 内容支柱 → 选题/脚本生产 → 账号矩阵分工 → 跨平台改编 → 发布巡检 → 数据复盘 → 阶段作战目标**」全闭环，让一个人像一支 MCN 团队一样运营自己的 IP。

**OPC（One-Person Company）原则**：一个人 + AI 中台 = 一支操盘团队。平台负责"团队该做的脏活累活"（选题批量生成、脚本工厂、一致性巡检、跨平台改写、数据复盘），人只做"主理人决策"（定位定调、终审发布、与粉丝互动）。

## 2. 九大作战模块（工作台分区，全生命周期贯通）

### 模块 A — IP 定位作战室（根，L0 + L1）
- 编辑独立 IP 定位卡：人设内核、受众画像、差异点、内容支柱、总调性、Slogan。
- 右侧实时「人设沉淀流」：接入 `user_persona`，对话里抽出来的人设自动浮现，可一键"采纳为定位依据"。
- **定位即判卷标准**：定位卡生成后，自动成为 `planBrandCheck` 的 `persona` 入参。

### 模块 B — 内容支柱矩阵（L2）
- 每个支柱一张卡：目标受众切片、内容方向、产出频率目标、关联账号、已产选题数 / 发布数。
- 支柱可下钻：点开看该支柱的选题池、脚本、资产、各账号排期。

### 模块 C — 选题 × 脚本生产引擎（L3，核心生产力）
1. **AI 批量选题**：基于定位 + 支柱，一次生成 10–20 条选题（含 hook/angle），存入 `content_ideas`。
2. **脚本工厂**：选题 → 一键扩成口播脚本 / 短视频脚本 / 图文稿，落 `content_assets(kind='script')` 并回写 `content_ideas.script_markdown`。
3. **人设巡检内嵌**：每条选题 / 脚本保存时自动调 `planBrandCheck` 打 `persona_check_score`，冲突项红标。
4. **生产流水线看板**：`idea → approved → produced → published` 状态机（表已支持）。

### 模块 D — 账号矩阵作战分工（L4 + L5）
- 账号列表：平台 / 昵称 / 调性 / 绑定支柱 / 是否主账号 / 已发布数。
- **跨账号排期板**：日历按账号着色（复用现有 `CalendarBoard` / `ACCOUNT_COLORS`），拖拽排期，每条排期绑定 `account_id` + 来源 `idea_id`。
- **一键多平台改编**：同一选题 → 按各账号调性自动改写标题 / 钩子 / 口播风格（AI 改写，不自动发布）。

### 模块 E — 发布一致性巡检（L1 × L3 × L5）
- 发布前巡检：草稿 vs 定位打分（复用 `planBrandCheck`）。
- 周期性「IP 一致性体检」：扫描近 30 天发布内容 vs 定位，输出偏离预警（conflict / off_tone 汇总）。

### 模块 F — 作战数据驾驶舱（L7）
- 阶段目标卡（OKR 式：本季涨粉目标 / 发布频次 / 支柱覆盖）。
- 指标看板：涨粉、发布数、支柱覆盖热力、人设一致率（**先 mock + 留 `ip_metrics` API 位**）。
- 周 / 月作战复盘：复用 `coachOrchestrator` 的 `planReview` 引擎，视角切到 IP 运营。

### 模块 G — 跨平台改编工坊（L3 × L4，模块 D 的子能力，单列强调）
- 输入一条母稿（脚本 / 选题），选择目标账号，AI 按该账号 `tone` + `pillar_mapping` 生成平台适配版（标题 / 钩子 / 口播风格 / 篇幅）。
- 产出为"待发布草稿"进入对应账号排期，主理人终审。

### 模块 H — 人设闭环中枢（L0 × L1）
- 把 `user_persona`（对话沉淀 + 手动编辑）与 `ip_positioning` 双向关联：
  - 对话沉淀的人设 → 提议更新定位（主理人确认）。
  - 定位变更 → 触发"历史内容一致性复检"任务。

### 模块 I — 阶段作战目标管理器（L0 × L7）
- 把 IP 阶段目标与人生主路径 `goals` 5 层**可选联动**（解耦但可挂接），让 IP 操盘与个人成长主线对齐。
- 目标进度驱动 F 模块看板的"目标 vs 实际"对比。

## 3. 目标用户与核心场景

### 3.1 目标用户（Who）
- **主用户**：以"个人 IP / 知识博主 / 小品类创作者"身份运营内容的个人（即 FlowSpark 主用户群），希望像一支团队一样经营自己的账号，但只有一个人。
- **核心特征**：多平台分发（视频号 / 抖音 / 小红书等）、内容方向容易发散、缺乏"我到底是谁、为谁创作"的清晰锚点、复盘靠感觉而非数据。

### 3.2 核心痛点（Why now）
| 痛点 | 现状 | 平台要解决 |
|---|---|---|
| 定位模糊 | 开了号但说不清"我是谁、为谁创造价值" | 给一套可填写、可沉淀、可复用的定位锚点 |
| 一人多号混乱 | 多平台账号各自为战，调性/排期对不齐 | 账号矩阵统一管理 + 一张排期总览 |
| 内容发散 | 选题随灵感，与定位/支柱脱节 | 以定位+支柱为源头驱动选题与排期 |
| 一致性失守 | 发着发着就"不像自己了"，没人提醒 | 发布前/周期性的 AI 一致性体检 |
| 复盘无据 | 涨粉/覆盖靠肉眼，不知道哪根支柱缺位 | 阶段目标 + 指标看板（先 mock，留真实接入位） |

### 3.3 典型使用场景（Jobs to be done）
- **场景 1（立根）**：新用户首次进入 → 在定位室填"我是谁/为谁/差异点"，并把对话里 AI 抽出来的人设一键采纳为定位依据。
- **场景 2（排兵）**：主理人把多个平台账号录入矩阵，给每个账号绑定位支柱与调性，在一张排期板上安排本月内容。
- **场景 3（体检）**：发布前点开巡检面板，看 AI 给待发内容的"像不像我"打分，红标偏离项，改完再发。
- **场景 4（复盘）**：月底打开驾驶舱，看本季涨粉目标完成度、哪根内容支柱发太少、人设一致率趋势。

## 4. AI 能力说明（产品视角，非技术实现）

> 本节只描述"用户能感知到的 AI 能力"，不涉及函数/表结构。技术实现细节见开发阶段单独文档。

| 用户能感知的能力 | 在平台里用在哪 | 用户看到的结果 |
|---|---|---|
| **人设一致性判卷** | 发布前巡检、周期性体检（模块 E）；也是定位室的判卷标准 | 每条内容一个"像不像我"评分 + 偏离点说明，冲突项红标 |
| **对话沉淀人设** | 定位室右侧"人设沉淀流"（模块 A） | 对话里 AI 抽出的"你可能是这样的人"自动浮现，可一键采纳为定位依据 |
| **周期作战复盘** | 驾驶舱的周/月复盘（模块 F） | 一份基于定位+支柱的运营复盘建议 |
| **按支柱聚合** | 支柱矩阵下钻（模块 B） | 点开一根支柱，看到它的选题池/资产/排期总览 |

**本期不做、但已规划在愿景的 AI 能力**：AI 批量选题与脚本工厂（模块 C）、跨平台一键改编（模块 G）、对话自动提议改定位（模块 H）。

## 10. 本期模块逐功能设计方案（A / B / D / E / F 详版）

> 本节为 **v1.1 拍板后**的本期范围（定位 + 矩阵 + 排期 + 看板 + 巡检）的功能级细化，按「页面结构 / 用户价值 / 核心功能（用户视角）/ 边界（本期不做）」展开。每个模块的详细设计维度一致，便于评审。

### 模块 A — IP 定位作战室（L0 根）

- **页面结构**：左侧「定位编辑卡」+ 右侧「人设沉淀流」双栏。
- **用户价值**：让"我是谁"第一次变成可填写、可沉淀、可复用的一张卡；并通过对话沉淀流把 AI 已经了解的"你"直接变成定位依据，降低填写门槛。
- **核心功能（用户视角）**：
  - 填写：人设内核、受众画像、差异点、内容支柱（可增删多张）、总调性、Slogan、一句话定位总结。
  - 采纳：右侧人设沉淀流展示 AI 从对话中抽出的"你可能是这样的人"，每条可一键"采纳为定位依据"，写入定位卡对应字段。
  - 判卷标准：定位卡填好后，自动成为后续所有内容"像不像我"的打分基准。
- **边界（本期不做）**：不做"对话自动改定位"（属愿景 H 模块）；本模块仅手动编辑 + 采纳沉淀。

### 模块 B — 内容支柱矩阵（L2）

- **页面结构**：支柱卡片网格（每支柱一张卡）+ 点开的下钻抽屉。
- **用户价值**：把模糊的"我要做几类内容"变成可见、可管理、可下钻的支柱矩阵，让内容方向不发散。
- **核心功能（用户视角）**：
  - 每张支柱卡展示：目标受众切片、内容方向、关联账号数、已产选题数、已发布数。
  - 下钻：点支柱卡 → 看到该支柱下的选题池、内容资产、各账号排期，一屏掌握这根支柱的全貌。
- **边界（本期不做）**：支柱的"产出频率目标"仅作展示，不做达成度算法/预警。

### 模块 D — 账号矩阵作战分工（L4 + L5，本期主力）

- **页面结构**：上部「账号列表网格」+ 下部「跨账号排期板」（日历视图，按账号着色）。
- **用户价值**：一个人管多平台不再靠脑子记——账号归谁、调性如何、本月发什么，一张图看清。
- **核心功能（用户视角）**：
  - 账号管理：录入/编辑多平台账号（平台、昵称、调性、绑定支柱、是否主账号），主账号高亮。
  - 跨账号排期板：所有账号的排期在一张日历上按账号配色呈现；支持拖拽改期、点空白新增；每条排期可关联一条来源选题。
- **边界（本期不做）**：不自动发布、不跨平台一键改写（属愿景 G 模块）；排期板预留"来源选题"关联位，为后续改编工坊留口。

### 模块 E — 发布一致性巡检面板（L1 × L3 × L5）

- **页面结构**：两个子区 —「待发布巡检」+「近 30 天一致性体检」。
- **用户价值**：发内容前有人提醒"这段不太像你"，月底有人告诉你"这 30 天哪根支柱跑偏了"，避免 IP 人设悄悄失守。
- **核心功能（用户视角）**：
  - 待发布巡检：列出未来 7 天待发布内容，逐条给出"像不像我"评分，冲突项红标 + 偏离说明，主理人改完再发。
  - 周期性体检：扫描近 30 天已发布内容 vs 定位，输出偏离条数、Top 偏离支柱汇总卡。
- **边界（本期不做）**：只出预警与说明，不自动改内容（修改交回人）。

### 模块 F — 作战数据驾驶舱（L7，mock 先行）

- **页面结构**：顶部「阶段目标卡（OKR 式）」+ 指标看板（涨粉 / 发布数 / 支柱覆盖热力 / 人设一致率）。
- **用户价值**：让"我觉得这个月还不错"变成"目标完成 70%、经典解读支柱只发了 2 条、人设一致率 92%"，复盘有依据。
- **核心功能（用户视角）**：
  - 阶段目标卡：手动设本季涨粉目标 / 发布频次 / 支柱覆盖，看板对比"目标 vs 实际"。
  - 指标看板：涨粉、发布数、支柱覆盖热力、人设一致率图表化呈现。
  - 周/月作战复盘：基于定位+支柱生成一份运营复盘建议。
- **边界（本期不做）**：指标数据本期为示例数据（mock），真实平台数据接入留接口位，不在本期强接。

### 本期模块贯通关系（用户视角）

```
A 定位室（定调："我是谁"）
   │ 驱动
   ▼
B 支柱矩阵（"我做哪几类内容"）
   │ 驱动
   ▼
D 账号排期（"各平台发什么、何时发"）
   │            │
   │            └─► E 巡检（发布前/周期"像不像我"）
   │
   └────────────► F 驾驶舱（目标 vs 实际，复盘有据）
```

用户路径闭环：**先定根（A）→ 立支柱（B）→ 排兵（D）→ 发布前体检（E）→ 月底复盘（F）**。

### 本期成功标准（验收口径）

- **可立根**：新用户能在一屏内填完定位卡，并能从人设沉淀流一键采纳至少一条对话人设。
- **可排兵**：能录入 ≥2 个平台账号并绑定支柱；排期板上能看到跨账号着色排期、可拖拽。
- **可体检**：发布前巡检对未来 7 天内容给出评分与红标；周期性体检产出近 30 天偏离汇总。
- **可复盘**：驾驶舱展示阶段目标卡 + 四项指标（mock 数据）+ 一份复盘建议。
- **不越界**：本期无自动发布、无脚本工厂、无跨平台改写、无真实数据强接。
